# 리소스 정리 체크리스트

실습 종료 후 과금 위험 리소스를 삭제하고, 삭제 완료 근거를 기록합니다.
**아래 항목은 실제로 삭제하고 확인한 뒤 체크(`[x]`)하고 확인 시각과 근거를 적습니다.**

- 리전: 서울 (ap-northeast-2)
- 정리 전제: 외부 접속 증빙 스크린샷과 평가 시연이 모두 끝난 뒤 진행 (삭제하면 접속 증빙을 다시 만들 수 없음)

## 삭제 순서와 이유

의존 관계가 있어서 **아래 순서대로** 지웁니다. 순서를 어기면 "의존성 있음" 오류로 삭제가 막힙니다.

1. EC2 인스턴스 종료 → 인스턴스가 서브넷, SG, 퍼블릭 IP를 사용 중이므로 가장 먼저
2. EBS 볼륨 확인 → 루트 볼륨은 "종료 시 삭제"로 함께 삭제되지만, 남아 있으면 과금되므로 직접 확인
3. Elastic IP 확인 → 할당한 적이 없어야 정상. 있다면 Release
4. Internet Gateway 분리(Detach) 후 삭제 → VPC에 연결된 채로는 삭제 불가
5. Subnet, Route Table 삭제 → 라우팅 테이블은 서브넷 연결을 해제한 뒤 삭제
6. Security Group 삭제 → 인스턴스 종료 후에 가능
7. VPC 삭제
8. 키페어 삭제 (과금은 없으나 정리 대상으로 기록)

## 필수 확인 항목

| 완료 | 리소스 | 확인 방법 | 확인 근거 (시각 / 상태) |
|---|---|---|---|
| [ ] | EC2 인스턴스 (`Codyssey-web`) | 인스턴스 목록에서 상태가 **종료됨(Terminated)** | |
| [ ] | EBS 볼륨 | EC2 → 볼륨 목록이 비어 있음(실습 인스턴스 볼륨 없음) | |
| [ ] | Elastic IP | EC2 → 탄력적 IP 목록이 비어 있음 (할당한 적 없음) | |
| [ ] | Internet Gateway | VPC에서 Detach 후 삭제, 목록에서 사라짐 | |
| [ ] | VPC (`Codyssey-VPC`) | VPC 목록에서 사라짐 (Subnet, Route Table, SG 포함) | |

## 주의 사항

- **기본 VPC와 이전 과제 리소스는 이번 정리 대상이 아닙니다.** 삭제하지 않습니다.
  - 단, 같은 계정의 다른 인스턴스가 중지 상태로 남아 있으면 연결된 EBS 볼륨은 계속 과금될 수 있으므로 별도로 확인합니다.
- 리전 필터가 **서울**인지 확인한 상태에서 목록을 확인합니다. 다른 리전에 만든 리소스가 있으면 놓치기 쉽습니다.
- 퍼블릭 IPv4 주소는 인스턴스 종료와 함께 반환됩니다.
